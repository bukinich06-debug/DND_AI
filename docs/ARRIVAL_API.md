# API контракт: описание прибытия игрока

## Проблема

Когда игрок меняет локацию (мгновенный телепорт или прибытие в конец путешествия), ему нужно увидеть описание нового места: где он находится, что видит вокруг.

Старый подход — отдельный агент **World look** — был отключён. Теперь описания мест даёт **Master** (главный рефери).

## Решение

UI должен вызвать **`POST /api/location/describe`** сразу после того, как локация игрока изменилась:

- после `PATCH /api/location/player` (клик на карту)
- после `POST /api/location/player/advance` с прибытием (`travel: null` в ответе)
- после любого вызова, который меняет `player.locationId`

## API: `POST /api/location/describe`

### Запрос

```json
{
  "campaignId": "string",
  "playerId": "string"
}
```

Оба поля обязательны.

### Ответ (200 OK)

```json
{
  "description": "string",
  "locationId": "string",
  "locationName": "string"
}
```

- `description` — текст от лица мастера, описывает текущую локацию игрока (1–3 предложения)
- `locationId` — id локации, где игрок находится
- `locationName` — название места (для отображения в UI)

### Пример

```json
{
  "description": "Вы стоите на деревенской площади Красного Утёса. Вокруг — низкие каменные дома с соломенными крышами, люди занимаются своими делами. На севере виднеется старая таверна «Медный Котёл».",
  "locationId": "clx9abc123",
  "locationName": "Красный Утёс (площадь)"
}
```

### Использование в чате

Добавьте `description` в массив сообщений как ответ ассистента:

```typescript
messages.push({
  role: 'assistant',
  content: response.description
});
```

Это позволит игроку видеть описание места в истории чата.

## Когда вызывать

### ✅ Вызывать обязательно

1. После `PATCH /api/location/player` (смена места на карте)
2. После `POST /api/location/player/advance` **когда `travel` стал `null`** (прибытие)

### ❌ Не вызывать

1. Во время путешествия (`travel !== null` после `advance`) — игрок ещё в пути
2. Когда игрок просто ходит по одной локации (например, по комнатам здания)
3. Во время хода игрока (`POST /api/turn`) — там Master сам описывает окружение по запросу

## Отличие от `/api/turn`

| | `/api/turn` | `/api/location/describe` |
|---|---|---|
| Когда | Игрок что-то делает или говорит | Игрок прибыл в новое место |
| Контекст | История диалога, действие игрока | Только текущая локация |
| Ответ | Может быть проверка навыка, действия NPC | Только описание места |
| Кто | Планировщик → Master / NPC | Только Master |

`/api/turn` используется для **хода игрока** (диалог, действие, осмотр по запросу).

`/api/location/describe` — для **автоматического** описания при прибытии, без явного запроса от игрока.

---

## Резюме для UI-команды

1. **Обязательный вызов:** после смены локации игрока вызовите `POST /api/location/describe { campaignId, playerId }`.
2. **Добавьте в чат:** ответ `description` как `{ role: 'assistant', content: ... }`.
3. **Не путайте с turn:** `/api/turn` — для действий игрока; `/api/location/describe` — для arrival.
